## 1. 快速开始

### 1.1 安装与启动

**要求**：macOS，Python 3.11+，Node.js 18+，npm

```bash
# 克隆项目
git clone <仓库地址> personal-info-monitor
cd personal-info-monitor

# 一键初始化（仅需执行一次）
./pim setup

# 作为后台服务安装（推荐，登录后自动启动）
./pim install-service
```

安装完成后访问：`http://127.0.0.1:8000`

**日常管理命令**：

```bash
./pim status          # 查看运行状态与 atoms/relations feature flag
./pim stop            # 暂停服务
./pim logs            # 实时查看日志
./pim backup          # 备份数据
```

### 1.2 首次登录

首次访问前端时，系统会自动从本地服务读取 API Key 并完成认证，无需手动输入。

若需手动查看 API Key：

```bash
cat ~/.pim/data/runtime-secrets.json
```

### 1.3 添加第一个监控源

1. 点击页面左侧「**源管理**」
2. 点击「**添加源**」，粘贴想要监控的 URL
3. 系统会自动探测内容类型（网站/RSS/X/YouTube/播客）
4. 确认配置后保存

第一次抓取通常在 1-5 分钟内完成。

## 2. 监控源管理

### 2.1 支持的源类型

| 类型 | 说明 | 典型场景 |
|------|------|---------|
| **website** | 网页抓取，自动提取正文 | 博客、新闻、公司官网 |
| **rss** | RSS/Atom 订阅源 | 技术博客、新闻聚合 |
| **x** | X（Twitter）用户/关键词 | 实时动态、话题追踪 |
| **youtube** | YouTube 频道新视频 | 技术演讲、教程更新 |
| **podcast** | 播客 RSS 新集数 | 行业播客 |

### 2.2 添加网站源（website）

适用于没有 RSS 的博客或官网。

**步骤**：
1. 输入目标网页 URL
2. 系统自动探测内容结构
3. 设置抓取间隔（默认 60 分钟）
4. 若目标网页需要登录，勾选「需要认证」并配置凭据

**配置项说明**：

| 配置 | 说明 | 建议值 |
|------|------|-------|
| 抓取间隔 | 每隔多少分钟重新抓取 | 新闻类 30 分钟，博客类 120 分钟 |
| 额外 URL | 同一来源的其他页面 | 如 `/news`、`/blog` |
| 关键词过滤 | 只保留命中关键词的内容 | 内容量大时开启 |

### 2.3 添加 RSS 源

RSS 是最稳定的订阅方式，推荐优先使用。

**步骤**：
1. 输入 RSS feed URL（通常以 `.xml` 或 `/feed` 结尾）
2. PIM 自动识别为 RSS 类型
3. 设置抓取间隔

**提示**：若只有网站 URL，PIM 会自动尝试发现该网站的 RSS 地址。

### 2.4 添加 X（Twitter）源

由于 X API 限制，PIM 支持多种采集策略，自动选择可用方式。

**支持的输入格式**：
- 用户主页：`https://x.com/username`
- 话题标签：`#AI`（通过 RSSHub 采集）

**认证方式**（按推荐优先级）：

| 方式 | 说明 |
|------|------|
| RSSHub | 无需 X 账号，依赖公共 RSSHub 实例 |
| 浏览器 Cookie | 在「认证配置」中保存 `auth_token` + `ct0` |
| X API Key | 官方 API，需申请开发者账号 |

**配置浏览器 Cookie**：

1. 在浏览器开发者工具中，访问 `https://x.com` 后复制：
   - `auth_token` 的值
   - `ct0` 的值
2. 在 PIM「设置 → API 密钥」中填入

### 2.5 添加 YouTube 频道源

**步骤**：
1. 输入频道 URL，例如 `https://www.youtube.com/@channelname`
2. PIM 自动找到该频道的 RSS feed
3. 新视频发布后自动抓取标题、描述和链接

**注意**：需要在「设置 → API 密钥」中配置 YouTube Data API Key，才能获取视频详情。

### 2.6 需要登录的网站

部分网站（如付费内容、企业内网）需要先登录。

**配置浏览器会话**：

1. 进入「设置 → 认证配置」
2. 创建新的浏览器会话
3. 点击「打开登录页面」，在弹出的浏览器中手动登录
4. 关闭浏览器后，登录状态自动保存
5. 创建源时选择对应的认证配置

### 2.7 高级穿透与反爬 (BPC 策略)

针对部分媒体网站（如彭博社、WSJ、部分本地新闻网）存在严格的计量付费墙或反爬机制，PIM 提供了基于 BPC (Bypass Paywalls Clean) 机制的高级配置能力。

**配置入口**：编辑某一个 website 信源，在弹窗底部找到「高级穿透（BPC 策略）」。

| 配置项 | 作用 | 适用场景 | 注意事项 |
|------|------|---------|---------|
| 伪装 User-Agent | 将请求的身份伪装为 `Googlebot` 或 `Bingbot` | 很多付费墙对搜索引擎爬虫放行 | 可能触发 Cloudflare 验证码，慎对普通网站使用 |
| 伪装 Referer | 声明流量来源于 Google 等搜索引擎 | 部分网站依赖 Referer 判断访问者是否为自然搜索流量 | |
| 随机 IP 伪装 | 自动生成并注入随机的 `X-Forwarded-For` 头 | 基于 IP 限频或限免阅读篇数的站点 | 可能导致需要登录状态的凭据失效 |
| SaaS 脚本拦截 | 在浏览器内核中阻断常见付费墙（如 Piano.io）的验证脚本 | 点击文章后弹出全屏付费遮罩的媒体网站 | 会增加一定加载开销，如果网站核心框架强依赖该脚本可能导致白屏 |
| 强制无痕模式 | 每次抓取都使用一个全新的隔离上下文，不带任何 Cookie | 针对每月限制免费阅读 N 篇的软付费墙 | **不可**与复用登录凭据选项同时开启 |

**提示**：所有的穿透策略均为“选择性开启”。强烈建议仅在目标网站明确出现抓取被挡（正文为空或提示截断）时，再针对性地打开对应的策略。此外，系统现在也会自动在页面解析前尝试提取底层的 `JSON-LD` 隐藏数据作为全文兜底，此功能全局自动生效。

### 2.8 源状态说明

| 状态 | 含义 |
|------|------|
| 正常 | 最近一次抓取成功 |
| 错误 | 连续抓取失败，查看错误详情 |
| 禁用 | 已手动关闭，不再抓取 |
| 等待中 | 距离下次抓取时间未到 |

连续失败超过一定次数后，源会自动禁用以节省资源。修复问题后重新启用即可。

## 3. 关键词监控与告警

关键词监控可以在新内容命中特定词语时高亮显示，并可选发送邮件告警。

### 3.1 创建关键词

进入「设置 → 关键词」，点击「添加关键词」。

**配置项**：

| 配置 | 说明 | 示例 |
|------|------|------|
| 关键词 | 要监控的词语 | `GPT-5`、`OpenAI` |
| 匹配方式 | 包含/精确/正则 | 见下表 |
| 匹配范围 | 标题/正文/全部 | 标题命中权重更高 |
| 颜色 | 高亮颜色标识 | 不同话题用不同颜色 |
| 邮件告警 | 命中时发送邮件 | 需先配置 SMTP |

**匹配方式说明**：

| 方式 | 行为 | 适用场景 |
|------|------|---------|
| `contains`（默认）| 包含即命中，不区分大小写 | 大多数场景 |
| `exact` | 全词精确匹配 | 避免误报 |
| `regex` | 正则表达式 | 复杂模式，如 `GPT-\d+` |

### 3.2 批量添加关键词

若需要同时监控多个相关词，可使用批量添加：

1. 点击「批量添加」
2. 每行输入一个关键词
3. 设置共享的匹配方式和告警配置

**推荐场景**：监控一个公司的所有产品名称。

### 3.3 邮件告警配置

1. 进入「设置 → 系统设置」
2. 填入 SMTP 配置：
   - Gmail：`smtp.gmail.com:587`，使用应用专用密码
   - 其他 SMTP 服务商按实际填写
3. 填写收件邮箱
4. 在关键词配置中勾选「邮件告警」

**Gmail 应用专用密码**：Google 账号 → 安全 → 两步验证 → 应用专用密码

### 3.4 关键词命中的内容

命中关键词的内容会在内容列表中：
- 显示彩色标签
- 标注命中的具体词语和范围

## 4. 内容阅读与管理

### 4.1 内容列表

主页内容列表支持多维度过滤：

| 过滤项 | 说明 |
|--------|------|
| 来源 | 按特定源筛选 |
| 类型 | website / rss / x / youtube / podcast |
| 已读状态 | 仅看未读 |
| 收藏 | 仅看已收藏 |
| 关键词命中 | 仅看命中关键词的内容 |
| 日期范围 | 按发布时间或抓取时间 |

### 4.2 全文搜索

搜索框支持全文检索，范围包括标题、摘要和正文。

**搜索技巧**：
- 多个词语之间为 AND 关系
- 搜索结果按相关度排序

### 4.3 Reader 模式

点击内容进入 Reader 视图，可获取：

- **完整正文提取**：去除广告和干扰元素
- **AI 摘要**：需开启 AI 功能
- **按需翻译**：点击翻译按钮，将摘要或全文翻译成中文

### 4.4 内容操作

| 操作 | 说明 |
|------|------|
| 标记已读/未读 | 管理阅读进度 |
| 收藏 | 保存重要内容 |
| 归档 | 整理读过的内容，不再显示在主列表 |
| 删除 | 永久删除 |

### 4.5 批量操作

- 长按或勾选多条内容后可批量标记已读
- 「全部标记已读」按钮可一键清空未读

## 5. 日报与摘要

### 5.1 日报（Digest）

日报按来源分类，汇总当天所有新内容。

**访问路径**：左侧菜单 → 「日报」

日报内容按源类型（网站/RSS/X/YouTube/播客）分组展示，每条显示：
- 标题（链接到原文）
- AI 摘要（若已生成）
- 发布时间

### 5.2 小时报

小时报提供更细粒度的内容聚合，适合实时监控场景。

- 每小时自动生成一次
- 在日报页面切换到「小时报」标签
- 适合 Agent 轮询最新内容

### 5.3 邮件日报

系统可每天自动将日报发送到邮箱：

1. 配置 SMTP（见 3.3 节）
2. 进入「设置 → 系统设置」
3. 开启「每日邮件日报」
4. 设置发送时间（默认早上 8 点）

## 6. AI 功能配置

AI 功能为可选模块，不影响基本监控和内容抓取。

### 6.1 支持的 AI 功能

| 功能 | 说明 | 需要 |
|------|------|------|
| 内容摘要 | 自动为长文生成摘要 | OpenAI / Ollama |
| 按需翻译 | Reader 中翻译全文 | OpenAI / Google Translate |
| 流式翻译 | 逐字流式输出翻译 | OpenAI |

### 6.2 配置 OpenAI

1. 进入「设置 → AI 模型」
2. 选择 OpenAI
3. 填入 API Key（以 `sk-` 开头）
4. 选择模型（推荐 `gpt-4o-mini`，性价比高）
5. 开启「AI 处理」

### 6.3 配置 Ollama（本地模型）

适合不想使用云端 API 的用户：

1. 先安装并启动 Ollama（建议延长模型驻留时间，避免批量翻译时反复加载）：
   ```bash
   export OLLAMA_KEEP_ALIVE=30m
   ollama serve   # 或 ollama run llama3
   ```
2. 进入「设置 → AI 模型」
3. 选择 Ollama
4. 填入 Ollama 服务地址（默认 `http://localhost:11434`）
5. 填入模型名称，如 `llama3`、`qwen2.5`、`qwen3`

> **性能提示**：应用调用 Ollama 时已默认启用流式输出。在「设置 → 智能引擎」中可为**写作模型**与**翻译模型**分别配置 Context 窗口（`num_ctx`）及是否关闭思维链（`/no_think`）。写作默认 8192、不关闭思维链；翻译默认 2048、关闭思维链。若仍感觉慢，请确认 Ollama 服务已设置 `OLLAMA_KEEP_ALIVE=30m`。

### 6.4 配置 Google Translate

用于翻译功能（无需 AI 摘要能力）：

1. 在 Google Cloud Console 申请 Translation API Key
2. 进入「设置 → API 密钥」
3. 添加 Google Translate API Key

## 7. 系统设置

进入「设置」页面管理所有系统配置。

### 7.1 内容保留策略

| 设置 | 说明 |
|------|------|
| 最大内容保留天数 | 超过时间的内容自动清理（0 = 永久保留） |
| 最大源数量 | 防止资源占用过多 |

### 7.2 抓取设置

| 设置 | 说明 |
|------|------|
| 并发抓取数 | 同时进行的抓取任务数，默认 20 |
| 默认抓取间隔 | 新源的默认抓取频率 |

### 7.3 数据清理

系统每周自动清理低信号内容（如无正文的空页面），也可手动触发：

- 「设置」→「维护」→「清理低信号内容」（先预览，再确认）

## 8. 数据管理

### 8.1 备份

```bash
./pim backup
```

备份内容：
- `pim.db`（SQLite 数据库）
- `backend/.env`（配置文件）
- `runtime-secrets.json`（运行时密钥）

备份文件保存在 `~/.pim/backups/`。

**重要**：`runtime-secrets.json` 包含加密主密钥，丢失后历史凭据将无法解密，务必随数据库一起备份。

### 8.2 导出源配置

若需迁移到新机器，可导出全部源配置：

```bash
./pimctl sources export --json > my-sources.json
```

### 8.3 数据目录

所有持久化数据默认存储在：

```
~/.pim/data/
├── pim.db                   # SQLite 主数据库
├── pim.log                  # 服务日志（滚动归档）
├── runtime-secrets.json     # API Key 和加密密钥（勿泄露）
└── dropped_tasks.log        # 任务丢弃记录（队列满时）
```

## 8.4 新闻原子库

结构化事实库（信息 / 观点 / 数据）存储在 `pim.db` 的 `atoms` 表中，与 Obsidian 等外部工具无关。

**启用：**

```bash
# backend/.env
ATOMS_ENABLED=true
ATOMS_RELATIONS_ENABLED=true   # 跨文印证/矛盾（P2，默认 false）
```

重启服务后，侧栏出现「原子库」，或访问 `/atoms`。

**日常操作：**

- 筛选：按类型、领域、验证状态、关键词
- 编辑：详情面板修改 payload JSON 并保存
- 验证：「标记已验证」确认人工审核通过
- **关联原子**（需 `ATOMS_RELATIONS_ENABLED=true`）：详情抽屉「关联原子」Tab 查看印证/矛盾、确认或拒绝、手建关系

**CLI：**

```bash
pimctl atoms list --json
pimctl atoms stats --json
pimctl atoms verify ATOM-20260520-00001 --json
```

P1 起新入库文章将自动 LLM 提取；历史数据可运行：

```bash
pimctl atoms backfill --limit 200 --since 2026-01-01
pimctl atoms atomize <content_id>   # 单篇重提取
```

**跨文关系（P2）：**

新入库的信息/数据原子会自动推断印证/矛盾候选（默认 `verified=false`）。批量重跑：

```bash
pimctl atoms relations reconcile --limit 500 --since 2026-01-01
pimctl atoms relations list --atom-id ATOM-20260520-00001 --json
pimctl atoms relations verify REL-20260520-00001 --json
```

印证确认后，两端原子的 `fact_confidence` 各上调 0.05（上限 1.0）。

## 9. 常见问题

### 服务无法访问

```bash
./pim status    # 检查是否在运行；并显示 atoms / relations feature flag
./pim logs      # 查看最近错误
```

若端口 8000 被占用：

```bash
lsof -i :8000   # 找到占用进程
./pim start     # 重新启动
```

### 源一直抓取失败

1. 检查 URL 是否可正常访问
2. 若是登录保护的网站，检查认证配置
3. 对于 X 源，检查 Cookie 是否过期
4. 查看源详情页的「最后错误」信息

### 内容抓取后为空

- **网站源**：目标网站可能使用 JavaScript 渲染，尝试开启浏览器会话模式
- **RSS 源**：检查 RSS feed 是否包含全文（部分 feed 只提供摘要）

### AI 摘要没有生成

1. 确认「设置 → AI 模型」中 API Key 已配置且有效
2. 确认「AI 处理」开关已开启
3. 查看后端日志中的 AI 相关错误

### 关键词告警邮件没有收到

1. 检查 SMTP 配置是否正确
2. 检查垃圾邮件文件夹
3. 确认关键词配置中勾选了「邮件告警」
4. 查看日志中 `email` 相关的错误

### 如何重置 API Key

```bash
# 删除当前密钥文件，下次启动会自动生成新密钥
rm ~/.pim/data/runtime-secrets.json
./pim stop && ./pim install-service
```

**注意**：重置 API Key 后，所有已保存的认证配置（如浏览器 Cookie）仍然有效（它们使用加密密钥保护，与 API Key 独立）。
